Make the Develop ladder actually work

A research-backed enhancement spec — keep the professional ladder, fix what happens inside each stage: forward-only progression, per-stage versions, approval gates, real story frameworks, deeper scene cards, a Step Outline stage, and Adapt as a mode. Mapped to what TFM already has.

Verified against authoritative craft sources + current tool docs   19 Jun 2026

The ladder in the screenshot — Logline → Synopsis → Treatment → Beats → Scenes → Draft → Coverage — is already a professional studio development path. The problem is never the workflow; it is that each stage today is a one-shot generation with no memory, no forward logic, no versions, and no gate. This spec keeps the structure and upgrades the mechanics. Crucially, TFM already owns the spine needed: the WGA colour-revision wheel, the ApprovalRequest engine, the unified AiService, and the ScriptScene model. This is reuse and wiring — not new infrastructure.

The white space (validated). Across Sudowrite, Final Draft 13, WriterDuet, Arc Studio Pro, Plottr, NolanAI/FinalBit, Squibler, Saga and the AI-coverage tools, no product fuses all six of: staged development ladder · version management · approval gates · professional frameworks · grounded scene diagnostics · coverage. Each owns two or three. A tool that threads frameworks → scene diagnostics → coverage through one version-controlled, approval-gated, data-grounded pipeline is category-creating. (Variety/Motion Picture Editors Guild test, Oct 2025: AI loglines matched humans but analytical notes were "an almost total fail" — so the edge is diagnostics computed against your own structured beats/scenes, not re-derived from a PDF.)

The corrected pipeline

The professional order is confirmed across MasterClass, StudioBinder, Final Draft and Wikipedia. One real change: a Step Outline belongs between the scene work and the draft — it is the scene-by-scene roadmap that removes the cliff-jump from outline to pages.

Logline→ Synopsis→ Treatment→ Beats→ Scenes→ Step Outline ✦→ Draft→ Coverage

Nested like Russian nesting dolls, each fits inside the next (Final Draft). Treatment = present-tense prose, ~7–12 pp selling version or 30–80 pp working version. Beats = structural skeleton. Scenes = scene cards (fields below). Step Outline = one paragraph per numbered scene — the draft-ready map. Sources: studiobinder.com/blog/script-outline-template-example, en.wikipedia.org/wiki/Step_outline, masterclass.com/articles/how-to-outline-a-screenplay, finaldraft.com/learn/going-from-outline-to-script.

Distinction to encode: Logline / Synopsis / Treatment are selling documents others read; Beats / Scenes / Step Outline are the writer's internal tools. The UI should label them so the ladder reads as two bands (Pitch · Build), not one flat assembly line.

The eight enhancements

1Advance always moves forward

behaviour fix Today advance() finds the first state==='wait' stage, so once Beats exist it can re-fire Treatment. The button must mean one thing: "take the current approved stage and generate the next layer." Never backward unless explicitly asked.

Build: track a currentStage index; Advance generates stages[current+1] from the approved output of stages[current]; disable Advance until the current stage is Approved (see #3). Backward = an explicit "Revisit" action that forks a version, never an overwrite.

Validates user point #1. Industry analogue: the step-deal — each layer is contractually gated behind sign-off on the prior one (WGA Screen Compensation Guide; gideonsway step-deal).

2Versions per stage, not regenerate-overwrite

new modelreuse colour wheel Regenerate must create a new version, not replace. Each stage keeps V1 · V2 · V3 with ◀ ▶ switching; actions per version: Regenerate · Duplicate · Compare · Promote to Approved.

Build: new DevelopmentStage + StageVersion rows (schema below). Reuse TFM's existing colour-revision wheel (revision-wheel.util.ts, the WGA order White→Blue→Pink→Yellow→Green→Goldenrod…) to colour-tag versions — the same convention Arc Studio Pro auto-applies. Compare reuses the diff already built for Revisions.

Validates point #2. WriterDuet keeps "infinite history" + snapshots; Arc Studio auto-snapshots + named snapshots + green/red compare + branch/merge (writerduet.com/article/256-timeline, help.arcstudiopro.com/guides/draft-revision-management). TFM already has the colour wheel + revision diff.

3Approval gates: Draft → Review → Approved → Locked

reuse ApprovalRequest Formalise the states the screenshot already hints at. Only an Approved stage unlocks the next. This prevents generating scenes from unfinished beats, or a draft from bad scene work.

Build: a status on each StageVersion (DRAFT · REVIEW · APPROVED · LOCKED). "Promote to Approved" inside a project routes through the ApprovalRequest engine we just wired (single Producer step, configurable later) — so stage sign-off uses the same inbox as Distribute/Breakdown. Standalone (no project bound) promotes directly. Advance (#1) checks the current stage is Approved/Locked.

Validates points #1 + #3. Studio practice: producers won't authorise the script until the treatment/outline is approved (screencraft.org/blog/to-outline-or-not). Final Draft "locked pages" = the production freeze analogue (kb.finaldraft.com). TFM's ApprovalRequest + the colour wheel's isLocked already model this.

4Beats get a framework picker

new When generating Beats, choose the structure. The engine then generates against that framework's real beats and labels each beat by name.

Feature frameworks
  • Save the Cat (Snyder) — 15 beats
  • The Paradigm (Field) — 3 acts + plot points
  • Hero's Journey (Vogler) — 12 stages
  • Monomyth (Campbell) — 17 stages
  • Story Circle (Harmon) — 8 steps
  • 8-Sequence Method (Daniel/Gulino) — 8 sequences
TV / series
  • Network hour — Teaser + 5 acts (+Tag), A/B/C strands
  • Sitcom half-hour — Cold open + 2–3 acts + Tag
  • Cable / streaming — 5-act shape, breaks stripped
  • Limited series — nested season arc ⊃ episode arcs

Validates point #4. Full verified beat lists are in the appendix so the picker ships with real data. Flag: the 8-Sequence labels are functional, not canonical proper nouns (treat as descriptors). Sources: savethecat.com, sydfield.com, channel101 wiki (Harmon, verbatim), en.wikipedia.org/wiki/Hero%27s_journey, screencraft.org TV act structure.

5Scenes become real scene cards (the differentiator)

new fields Not a bare scene list. Each scene card carries the fields professionals actually use — and the one almost no tool exposes: the value/charge turn.

FieldSource of truth
Scene # · INT/EXT · Location · Day/Night · one-line synopsisStandard heading (already on ScriptScene)
Purpose / goal · Conflict (obstacle) · StakesStudioBinder G.O.D.D.; Save the Cat hero/goal/obstacle
Characters present · Story thread (A/B/C)Arc Studio storyline + character tags
Charge at open → charge at close · Turn type (action | revelation)McKee value-charge — every scene must turn; only Save the Cat (+/-) and Arc Studio (value curve) touch this
Emotional shift · page/duration goal · notesSave the Cat emotional start/end

Build: extend ScriptScene (additive columns) or a SceneCard child; the Doctor's existing scene diagnostics (objective/obstacle/subtext/power-shift) already compute most of this — wire them to populate the card. Surface a McKee "flat-scene" warning when open-charge == close-charge.

Validates + deepens point #5. McKee: "no scene that doesn't turn… on action or on revelation" (mckeestory.com/do-your-scenes-turn). Tool field models: savethecat.com scene cards, help.arcstudiopro.com/guides/the-plot-board, docs.plottr.com, finaldraft.com Beat Board.

6Adapt is a mode before the ladder, not a rung

restructure New project asks: Original Story or Adapt Existing Material. Adapt collects source (PDF/FDX/Word/Fountain/paste/online research) → produces Source Analysis → Adaptation Strategy, then feeds the same clean ladder (Logline → … → Draft). This is what we prototyped when "pick a direction" drops into Develop — formalise it as the entry mode.

Validates point #6. Keeps the ladder clean; the adapt directions become the agreed spine that seeds Logline/Synopsis.

7Add the Step Outline stage (Scenes → Step Outline → Draft)

new stage The biggest missing piece. After Scenes (cards), generate a Step Outline: one numbered paragraph per scene — the detailed roadmap that makes Draft generation a translation, not a leap.

Validates point #7. "The step between scene cards and the first draft… briefly details every scene, numbered in order" (en.wikipedia.org/wiki/Step_outline; en.wikipedia.org/wiki/Film_treatment). Final Draft: outlining first means drafting spends brain on craft, not "what happens next."

8Position: a studio development department, not an AI generator

positioning The combination below is the moat. Make coverage a gate between rungs ("here's the read on your treatment before you commit to beats") and compute all diagnostics against TFM's own structured beats/scenes — the exact place every competitor breaks.

"Final Draft + WriterDuet + a studio development department + AI" — version management · approval workflow · professional frameworks · scene diagnostics · coverage · rewrite tracking, threaded into one accountable pipeline.

Data model & architecture (mostly reuse)

Add

  • DevelopmentStage — projectId, documentId?, kind (LOGLINE…COVERAGE), order, currentVersionId, status.
  • StageVersion — stageId, n (V1/V2…), body (Json/text), framework?, colorCode (from the wheel), status (DRAFT|REVIEW|APPROVED|LOCKED), aiRunId, createdAt.
  • ScriptScene additive cols (or SceneCard): purpose, conflict, stakes, chargeOpen, chargeClose, turnType, thread.

Reuse (already in TFM)

  • AiService — every generation logged to AiRun (governance, retries, JSON).
  • Colour-revision wheel — version colour tags + lock.
  • ApprovalRequest engine — stage sign-off via the inbox just built.
  • Revision diff — powers Compare between versions.
  • Doctor scene diagnostics — populate scene-card fields.
  • On promote-to-final → branch a real ScriptRevision (the "save as draft" step) so it lands in Library/Reader.

  2. Need (want something)

Field Paradigm

  1. Setup (Act I, pp 1–10)
  2. Inciting Incident
  3. Plot Point I (≈ pp 25–30)
  4. Pinch / confrontation (Act II)
  5. Midpoint (centre)
  6. Plot Point II (≈ pp 85–90)
  7. Climax / Showdown (Act III)
  8. Resolution + Tag

8-Sequence Method labels functional

  1. Status quo & point of attack
  2. Predicament / lock-in (ends Act I)
  3. First obstacle / raise stakes
  4. First culmination / midpoint
  5. Aftermath / subplot rising
  6. Second culmination / highest stakes (ends Act II)
  7. New tension / resolution setup
  8. Resolution / climax

TV & limited series

Network hour: Teaser → Act 1 → 2 → 3 → 4 → (5/Tag); each act-out a turn. Sitcom: Cold open → Act 1 → 2 (+Tag). Cable/streaming: same 5-act shape, breaks stripped. Strands: A (lead plot) · B (character/emotional) · C (runner). Limited series: one season arc (≈ stretched 3-act) ⊃ per-episode arcs that each close a chapter.

Campbell's 17-stage monomyth also verified (Departure 1–5 / Initiation 6–11 / Return 12–17) — available as an advanced option. Vogler: "12 is not sacred" (scales 10–32).
