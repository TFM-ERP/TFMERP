Production · Locations Module

From a location database to a Location Department operating system

The module already holds remarkably rich data — needs, options, scout visits, clearance packs, tech recces, evaluations, permits, risks, payments, sun-path. The problem isn't the data; it's that the lifecycle is fragmented across six tabs and a deep modal, the connection to the rest of production runs on free-text strings, and the highest-value automations (call-sheet autofill, unit moves, per-location budget, a project map) are missing. This proposal benchmarks the leading film-location platforms, maps the current state, and reorganises the module around the real location lifecycle — clustering, merging, and wiring it into scheduling, call sheets, transport, travel, budget and assets.

The canonical location lifecycle

Every professional location workflow — studio, streamer, feature, commercial — follows the same spine. Best-in-class software makes each stage a tracked state with an explicit gate before the next:

Two hard gates the industry enforces: (a) a location can't be confirmed until it's cleared (permit granted → COI issued to that holder → signed agreement + insurance), and (b) a tech recce happens after selection and before the shoot so every department turns the choice into a plan. The current module has the data for both but enforces neither.

🛰 What leading platforms do well

  • Mobile-first field capture with offline sync — shoot photos/notes/GPS on a phone, sync later (SuperScout, Massif, Cadrage).
  • Virtual / 360° / VR scouting and drone media — explore before travelling.
  • AI brief-matching — "rustic bridge over a serene river" → curated candidates with logistics.
  • Centralised binder: addresses, permits, COIs, contracts, photos, contacts, notes in one record.
  • Mapping: base camp, parking, holding, catering, closure perimeter, camera positions on one map; draw the route, measure drive & walk time (Scribble Maps, Google Maps movement orders).
  • Integration with scheduling & call sheets so the chosen location flows downstream automatically.

🎬 The location department it must serve

Software should map to real roles, not a generic CRM:

  • Location Manager — secures locations, negotiates, owns permits/insurance, PR & crew safety on site.
  • Location Scout — finds & photographs candidates against the director's brief.
  • Location Coordinator — day-to-day: site visits, owner liaison, permit admin.
  • Assistant LM — prepares movement orders, organises tech recces for HODs, resident letters, end-of-day clear & restore.

Implication: the module needs role-aware permissions, an approval chain, a movement-order generator, a recce tool per department, and a compliance/clearance command centre — not just a card grid.

2 Current state — strong bones, fragmented surface

What exists in TFM today across the project Locations tab, the AssessModal, and the standalone Master Library.

✅ Already built (a real asset)

  • 6 inner tabs: Locations · Breakdown & options (need→options→lock + director sign-off) · Scout visits (multi-stop planner + transport) · Clearance packs (crew-ID public links, audited) · Report & plates (purpose-tagged photos, lookbook, sun-gating) · Readiness.
  • A deep AssessModal: pipeline stage + compliance gates (NOC/Agreement/Insurance), plus Documents, Permits (typed, OCR, authority routing), Security, Payments, 10-criterion Evaluation, Tech recce (per-HOD), Risk register.
  • A company-wide Master Library with usage history (timesUsed, totalSpent), compliance-expiry alerts, and a Google-Maps view with clustering + spend heatmap.
  • Ledger wiring: location fee, permit fee, security, payments all post to the project ledger.

⚠ The structural problem

  • String coupling. Stripboard, breakdown, call sheets and transport all reference a location by free-text. The only real link is one stamped column (ProductionStrip.locationId) set on Lock — with no Prisma relation. Rename a script location → the join silently breaks.
  • The lifecycle is hidden in a modal. Permits, recce, risk, budget and payments live behind "Assess", so the producer view and the field workflow never see the whole picture.
  • Downstream automation is missing. Call sheets carry address/hospital/basecamp/parking/daylight fields but they're filled by hand — the linked Location is never resolved at generation.
  • Two permit truths. A loose permitStatus string on Location vs the rich typed LocationPermit in Assess — they can disagree, and neither blocks a shoot date on expiry.
  • No project map, no unit moves, no per-location budget. The map is library-only; there's no movement order, drive-time, or budget-vs-actual per location.
Verdict: this is not a rebuild. ~80% of the data model is already production-grade. The work is re-surfacing it around the lifecycle, resolving the entity link so data flows, and adding the three missing operational surfaces — Map/GIS, Unit moves, and a unified Clearance/Compliance centre.

5 How it connects — and changes — the rest of the system

The redesign's biggest payoff is wiring. Resolve the Location entity (a real relation, not a string), and the whole production inherits it.
ModuleTodayAfter — and the effect on that module
Scheduling / stripboardString join; locationId stamped on lock, no relationStrip → real Location relation. Locking a location flows everywhere; sun-path + weather feed auto-schedule. Effect: stripboard shows real location status & gate.
Call sheetsAddress/hospital/basecamp/parking/map filled by handGeneration resolves the linked Location → auto-fills the whole location + safety block + daylight + attaches the movement-order map. Effect: call sheets become one-click and always correct.
Transport / dispatchfromLocation/toLocation stringsMovement orders & scout routes raise transport orders with real coordinates & drive-times. Effect: dispatch gets routable pickups, not free text.
Travel & accommodationNo link to locationsProximity: nearest hotels & airports to the unit base / location; per-location travel time. Effect: accommodation booked by distance-to-set.
Budget / costAd-hoc ledger postings; no per-location envelopePer-location budget vs actual (fee + permit + security + payments) commits & rolls up to the cost report. Effect: Locations becomes a real cost centre with variance.
Assets / rentalSeparate BookingLocationShared geocoding & map layer between production locations and rental bookings. Effect: one geographic source of truth.
Comms / approvalsDirector sign-off, permit routing, gates — three separate mechanismsOne unified location approval state + notifications; departments subscribe to a location. Effect: clear, audited sign-off chain.

7 Advanced features that lift it to studio standard

🗺 GIS & routing

Project map, base-camp/parking/closure overlays, draw-the-move with drive & walk time, movement-order export, geofenced arrival check-in (already in Comms).

📱 Offline field PWA

Capture candidates with photos + GPS + what3words offline; queue & sync; HOD recce on phone — matching the leading scout apps.

🤖 AI brief-matching

Match a director's brief against the Master Library & submissions; auto-tag photos by purpose; surface look-alike past locations.

🛡 Clearance automation

Permit→COI→agreement gate; authority lead-time reminders; auto-generate NOC/resident letters (EN/AR); insurance-expiry alarms.

💷 Location cost centre

Per-location budget vs actual, commitments, and a Locations line that rolls into the production cost report & EFC.

🎞 360 / floorplan media

PANO360 / FLOORPLAN / CAD / DRONE viewers (the enum values already exist), versioned, with auto lookbook & storyboard.

🌤 Weather + sun gating

Forecast feed + sun-path → schedule gates ("golden-hour only", "rain cover set"), and the call-sheet daylight block.

✅ Readiness & gates

One confirm gate (cleared + recced + risk-assessed + signed) producers can trust; blockers visible on the Board.

🔐 Role-aware permissions

LM / scout / coordinator / asst-LM / producer scopes; owner-PII reveal audited (OTP already exists for ID packs).

8 Phased roadmap — low-risk, additive, in this order

Phase 1 · Foundation

Make data flow before re-skinning.

  • Real Location relation on strips/call sheets
  • Call-sheet autofill from location
  • Unify permit status (one typed truth)
  • Per-location budget field

Phase 2 · Surfaces

Re-surface around the lifecycle.

  • Promote AssessModal → Location workspace
  • Board (lifecycle pipeline)
  • Clearance & Compliance centre
  • Project Map & Routes

Phase 3 · Advanced

Studio-grade operations.

  • Logistics / unit moves + movement orders
  • Offline mobile scout PWA
  • Weather feed · 360 media · AI matching
  • Budget-vs-actual rollup to cost report
Everything is additive and reversible, exactly like the dashboard work — new surfaces beside the existing ones, the entity-resolution done behind a compatibility shim so nothing breaks while it lands.
