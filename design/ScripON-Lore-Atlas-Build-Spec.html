Lore Atlas + consolidated intake

One spec to merge the redesigned 2-step intake, the 12-culture Lore Atlas (archetype lens · element roles & weight · deep cards · sacred-policy), and the lore-density bar into the existing Studio intake — plus the data model and AI wiring that make it real. No new parallel screens.

Schema · additive, one db:push
Approach · spec → approve → build in waves
Guardrail · mount-safe writes only

1Goal & non-goals

Fold every approved piece of our recent work into the one intake the system already uses, so a build's creative brief is richer and the Lore Atlas actually steers the AI ladder.

In scope

  • 2-step intake flow — Step 1 sources → Next → Step 2 brief; modes (Original / Adapt / Seed) genuinely differ.
  • Work source rename + (+) multi-add — many paste boxes, many files (PDF·FDX·Fountain·Word·EPUB·HTML), many URLs.
  • Project type on Step 2 with conditional episodes / minutes-per-ep / seasons (TV·Vertical) and industry-standard hints.
  • Lore Atlas — replaces the flat fantasy chip list: by-culture & by-archetype browse + search, element roles + weight, deep element card, two-tier sacred policy, the steering-not-generating note.
  • Lore-density bar — 6 named stops; the live note is the literal AI instruction.
  • Data + AI wiring — a seeded element library, the brief-builder extension, and removal of the duplicate standalone route.

Non-goals

  • No new top-level screen or rail item — this lives inside the Studio "Start a build" intake.
  • The Atlas does not write stories; it steers genre/texture on top of the Work source.
  • Performer names/photos remain out (unchanged rule).

2Data model — additive

One new reference model and a handful of additive columns on the existing IntakeProfile (already a JSON-heavy, per-project record with a buildId). Everything below is one db:push.

New model · NEW the seeded element library

model LoreElement {              // the one researched library; ~90 rows seeded
  id           String  @id @default(cuid())
  slug         String  @unique          // "djinn", "ghoul", "cosca-family"
  name         String
  culture      String                   // Arabian | Japanese | Norse | … (12)
  region       String?
  genres       Json                     // ["fantasy","horror"] | ["crime"] | ["romance"] …
  archetypes   Json                     // ["shapeshifter"],["death-omen"],["world-system"] …
  tier         String                   // FOLKLORE | SACRED_AWARE | HISTORICAL_PANTHEON | CARE
  blurb        String  @db.Text         // the one-line lore note
  origin       String? @db.Text
  variants     Json?                    // regional variants
  hooks        Json?                    // 2–3 story hooks (deep card)
  aliases      Json?                    // search synonyms ("fox spirit" → kitsune)
  sources      Json?                    // citations (deep card)
  active       Boolean @default(true)
  @@index([culture])
  @@map("lore_elements")
}

Living-religion deities/prophets are simply never seeded → they can never surface (hard lock by absence, belt-and-braces with the policy check in §4).

Extend · EXTEND intakeSteer() — turn selections into the brief the AI obeys

This is the load-bearing change. Today intakeSteer emits a flat "Add a high fantasy layer with Djinn, drawing mythology from Arabian; balance = MYTHIC." We replace that block with role-aware, density-anchored, guardrailed text — the same words the user saw.

// replaces the current i.fantasyOn block
if (sel = i.loreSelections?.length) {
  parts.push('LORE LAYER (steers genre/texture only — the Work source drives the story):');
  for (s of i.loreSelections)
    parts.push(`· ${name} (${s.culture}) — role ${s.role}, ${weightWord(s.weight)}.`);
  parts.push(DENSITY[i.loreDensity]);   // ← the rubric text below, verbatim
  parts.push(guardrailLines(selectedTiers, i.lorePolicy)); // sacred-aware / care / hard-lock
}

The density rubric — what each stop tells the model

StopOne-line definition injected into the briefScene share
OFFNo lore layer.—
ACCENTLore is decorative only; premise/midpoint/climax stay grounded; never resolve a plot turn with lore.~10–20%
SUBPLOTLore powers a B-story or recurring motif; the A-plot stays grounded.~25–35%
WOVENLore is a world-rule; the midpoint is lore-driven; premise & climax stay grounded.~40–50%
DRIVERLore is the central engine; inciting + midpoint + climax are lore-driven; the protagonist's goal is defined by it.~60–80%
SATURATEDFull mythic mode; the world runs on the lore end-to-end; realism is the contrast.~80–100%
