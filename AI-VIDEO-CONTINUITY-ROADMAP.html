Why the current renders feel like separate videos — and the exact, researched pipeline to make every 5-second beat carry character, continuity, dialogue and music into a 60–90s episode, then scale to a 60–80 episode series.

The one-line diagnosis. Today each clip is a independent text-to-video generation — no shared face, no carry-over from the previous shot, no audio. The fix is the standard 2026 micro-drama pipeline: lock a character anchor image → render with image-to-video → chain by last frame → let Seedance generate native audio → stitch per episode. Seedance 2.0 already supports every piece of this on the FAL key we use.

The five breaks

#BreakRoot cause
1Character driftNo reference image is passed — Seedance has nothing to lock the face/outfit to. We generate a text character bible but never turn it into an image.
2No scene continuityWe use text-to-video, not image-to-video — so no first-frame / last-frame handoff between shots.
3Silent clipsgenerate_audio is never set; reading_dialogue and audio_fx_ambiance from the prompt are never sent to the engine.
4No episode structureShots render as a flat pile of 41, not grouped into 60–90s episodes (the ladder already has an Episode map we don't use at render time).
5Concatenation ≠ continuityThe stitch joins clips end-to-end, but with no shared frames the cut is jarring.

Good news: the spec layer (script → shot grammar) and the engine governance, render, persistence and stitch are already built. The gaps are all in how we drive the engine — not new infrastructure.

② The "storyboard-anchored" route beats per-clip prompting

The most-used 2026 drama workflow doesn't prompt each shot blind. It generates one storyboard image first (a character/scene anchor — often a 3×3 nine-panel page), confirms it, then hands it to Seedance image-to-video as "visual DNA": character, wardrobe, location, lighting and palette are all locked from that image, and the motion prompt only describes the action. Character consistency becomes free because every beat derives from the same canvas.

Strategy A · recommended

Storyboard-anchored episodes

Per episode: 1 character anchor + a storyboard frame per ~15s chunk → image-to-video (native audio, multi-cut) → chain chunks by last frame → stitch.

  • best consistency look locked from shared images
  • cheapest ~4–6 video calls / episode
  • cuts inside a 15s clip act as your 5s beats
Strategy B · max control

Per-5s-scene chaining

Render every 5s beat as its own image-to-video clip, anchor + previous last frame each time, then stitch 12–18 per episode.

  • tightest control per-beat camera/lens
  • priciest 12–18 calls / episode
  • more places drift can creep in
Recommendation: ship Strategy A as the default (consistent, cheap, fast), and keep per-5s-scene as an advanced toggle for hero episodes that need shot-by-shot control. Both reuse the same anchor + chain + audio + stitch machinery.
