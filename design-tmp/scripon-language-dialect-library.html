Script Language, Dialect & Accent Library

The language a build is written in — set per script, defaulting to formal — with an authentic, professionally-grounded dialect/accent layer. Research-backed; built to be accurate, not decorative.

The one idea

This is not the interface language (that's the Arabic UI we already shipped). This is the language the screenplay itself is written in, chosen when you create/develop a build. Default stays Formal — Modern Standard Arabic (الفصحى). From there you pick a country and a specific dialect/accent (and most countries have several).

1 · The principle that makes it professional

Getting this right hinges on two facts that working screenwriters live by:

① Arabic scripts are diglossic

A real Arabic screenplay mixes two registers: action & scene description in فصحى/MSA, and dialogue in the characters' colloquial dialect (عامية). MSA is effectively "read-only" — nobody speaks it at home — so MSA dialogue reads as stiff and erases regional/ethnic identity. Prestige/historical/pan‑Arab dramas may stay all‑فصحى; contemporary realism uses the local dialect for voices.

So the choice isn't one switch — it's narration register (default فصحى) + dialogue register (formal فصحى or a specific dialect).

② Two kinds of variety, written differently

WRITE‑IT Arabic colloquial & Chinese topolects genuinely change the written words/grammar. The AI must compose the dialogue in that dialect.

ACCENT English/Spanish/etc. regional varieties are mostly phonetic. Best practice: do not misspell phonetically ("eye dialect" distracts the reader). Keep standard spelling, colour it with regional idiom/word‑choice, and put the accent in a parenthetical / scene‑note for the actor & dialect coach.

2 · The Arabic library

Default = الفصحى — Modern Standard Arabic (formal; also a Classical/Quranic register for period/scripture‑adjacent work, used carefully under the sacred guardrails). Below: the six dialect families → countries → the sub‑dialects inside them, each with a signature marker so generation is authentic, not generic. "I want" is the quickest fingerprint of a dialect.

3 · English — accents & dialects accent

Default = Neutral / General (General American or RP, per market). ~160 documented varieties; we seed the screen‑relevant ones, handled the professional way — idiom + an actor parenthetical, never phonetic misspelling.

British Isles

  • England: RP/Received, Estuary, Cockney (East London), Multicultural London (MLE), West Country, Brummie (Birmingham), Scouse (Liverpool), Mancunian, Yorkshire, Geordie (Newcastle)
  • Scotland: Glaswegian, Edinburgh, Highland
  • Wales: North & South Welsh (sing‑song)
  • Ireland: Dublin, Cork, Northern Irish (Belfast)

North America & wider world

  • USA: General American, Southern, New York, Boston, AAVE, Chicago/Inland‑North, Texan, Appalachian, Californian
  • Canada: Standard Canadian, Newfoundland
  • Other: Australian, New Zealand, South African, Indian, Irish, Caribbean/Jamaican Patois (borderline write‑it)

4 · Chinese & extensibility

Chinese varieties are largely mutually unintelligible — closer to separate languages. Default = Standard Mandarin (Putonghua). Seed the major groups: Mandarin (+ Beijing, Northeastern, Taiwanese Mandarin), Yue/Cantonese, Wu (Shanghainese), Min (Hokkien/Taiwanese), Hakka, Xiang, Gan, Jin. These are write‑it (Cantonese especially has its own written forms). The same model extends to Spanish (Castilian, Mexican, Rioplatense, Caribbean…), French (Metropolitan, Québécois, Maghrebi), Portuguese (European, Brazilian), Hindi‑Urdu, etc.

5 · Data model (per build)

Stored on the build/intake (additive — no migration risk; one db:push):

  • scriptLanguage — e.g. ar, en, zh (default: formal Arabic / or the UI locale)
  • variety — the dialect/accent id, e.g. ar-MSA (default), ar-EG-cairene, en-GB-cockney, zh-yue
  • dialogueRegister — formal (default) | colloquial  (write‑it languages)
  • narrationRegister — formal (default; action lines stay MSA/standard)
  • accentNote — optional free text for the parenthetical (accent languages)

Backed by a seeded LanguageVariety reference table: { lang, region/country, id, nameEN, nameNative, type: write|accent, isDefault, register, signatureMarkers[], examplePhrase, note } — the researched library above becomes this seed.

6 · How it steers generation

1
Write‑it + colloquial → the generator writes dialogue in the chosen dialect (using its signature vocab/particles/grammar from the seed), while action/sluglines/parentheticals stay فصحى/MSA. A scene‑note records the dialect ("الحوار باللهجة المصرية").
2
Write‑it + formal (default) → everything in فصحى/MSA — the safe pan‑Arab default you asked to keep.
3
Accent (English etc.) → dialogue in standard spelling, flavoured with region‑appropriate idiom/lexis; a one‑line parenthetical/scene‑note flags the accent for cast & dialect coach (no eye‑dialect).
4
The variety is also written into the brief, the coverage (market fit), and a casting/dialect‑coach note in the package — so it travels downstream, not just at generation.

Guardrails preserved: Classical/Quranic register and sacred figures stay under the existing sacred guardrail; dialect choice never overrides it.

7 · The UI (build intake)

Extends the intake's existing Target step (it already has a "Target language" field). New Script language control, searchable like the current target dropdowns:

Language ▸ Country / region ▸ Dialect / accent  ·  Register: ◉ Formal (default) ○ Colloquial  ·  optional accent note

Each dialect shows its native name + the "I want" fingerprint as a confidence cue (e.g. المصرية — عايز). Default lands on الفصحى so nothing changes unless chosen.

8 · Phasing

  • P1 — Arabic, deep & accurate. The full library above + the diglossic generation steering (the priority; verify the Arabic with you first).
  • P2 — English accents (idiom + actor‑note handling).
  • P3 — Chinese + the rest (Spanish/French/Portuguese…) as the same model.
