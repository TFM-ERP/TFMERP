ScripON Doctor · UX/UI Redesign Strategy — Wave 1 foundation

From admin panel to production command centre.

Design-first. This document fixes the architecture and the experience before a single screen is drawn: a brutally honest audit of today's Script Hub, a new workflow-based information architecture that ends feature-burial, the visual-hierarchy rules, the Reader-as-centrepiece concept, the design system, and dedicated desktop/tablet/mobile strategies. The Figma frames are built on top of this.

Roles: Senior Product Designer · UX Architect · Figma Design Lead · Film-Production Workflow Expert. Foundation derived from the ScripON Doctor spec + the Script Hub brief. Date: 17 June 2026.

The core problem, stated plainly: the most valuable tools were placed in a three-dot overflow, so the product reads as an admin panel and its power is invisible. The fix is not cosmetic — it is architectural. We reorganise around the way a production actually works and make the Script Reader the gravitational centre, with the AI Doctor as a visible dock, never an overflow item.

PHASE 2

New information architecture

Organised by production workflow, not the database or engineering convenience. A small, fast left rail of production stages — and the Reader at the centre of all of them.

The four core journeys

  • Develop / Adapt → draft — Seed or book/PDF → Doctor (Develop/Adapt) → branched draft lands in Library/Reader.
  • Import → produce — Library import → Reader → Breakdown (tag once) → Schedule & Budget (strips + cost).
  • Diagnose → rewrite → re-cost — Reader select scene → Doctor dock (diagnose) → rewrite/budget-fit variant → Apply → branched revision → re-cost via Schedule.
  • Revise → compare → distribute — New colour revision → Version compare (costed change report) → Reports/distribute.

Merge / split / lens decisions

  • Merge — Coverage + Diagnostics + Arc/emotion → one 'Insights' surface (reading the script three ways). — One mental model; one place to judge the script.
  • Merge — The 17 transforms (budget-fit, protagonist-swap, emotion, genre, ending, humour, intensity, …) → a single Doctor 'Rewrite' action grid. — Visible, scannable; no overflow; consistent variant→Apply→branch pattern.
  • Merge — Notes + comments + collaboration → one review layer pinned to scenes in the Reader. — Conversation lives next to the text it's about.
  • Split — 'Audio studio' (voice casting / sound design / render) → its own focused destination, not crammed into the Reader chrome. — Audio is a distinct craft with its own surface.
  • Lens, not page — Characters/Props/Locations/Wardrobe/Vehicles/VFX → filtered lenses inside Breakdown. — Six pages become one tag-once surface with views.
Six "pages" become lenses: Cast · Props · Locations · Wardrobe · Vehicles · VFX are filtered views of one tag-once Breakdown — grouped by how a production works, not by table.

PHASE 5

Design system

Tokens & surfaces

  • Shell / chrome — Cinematic charcoal — bg #0C0D10, panel #15171c, line #2a2e35. The frame recedes.
  • Reading surface — Warm 'paper' (near-white #F7F4EC) for the script canvas — deliberate contrast = focus, the one bright thing on screen.
  • Accent — Gold #C6A463 / #E6D2A2 for primary actions & active state; cream #F3ECDD text on dark.
  • Type — One humanist sans for UI (tight display headings, 15px body) + a mono/courier-like face for the script body to read like a screenplay.
  • Spacing — 8-pt grid, generous gutters, a max reading measure on the script column.

Status systems

  • Revision colours: White · Blue · Pink · Yellow · Green · Goldenrod · Buff · Salmon · Cherry · Tan (industry wheel)
  • Coverage grades: Excellent / Good / Fair / Poor
  • Recommendation: Pass · Consider · Recommend
  • AI confidence: high / needs-review band on every AI output

Element-category colour system (one tag, consistent everywhere)

CastPropsLocationsWardrobeVehiclesVFXSFXStunts

Component library

  • Cards (scene cards, variant cards, element chips)
  • Chips & tags (element categories colour-coded; revision colour pill)
  • Tables & lists (sortable, lens-filtered, bulk)
  • Status badges (grade, severity, confidence)
  • Action grid (the Doctor — replaces overflow)
  • Right Dock shell (tabbed, slide-in)
  • Empty states that coach the first action
  • Toasts / progress for AI runs
  • Forms (settings only — kept out of the daily path)

The Action Grid component is the antidote to the three-dot menu: contextual actions laid out as a scannable, labelled grid — discoverable, not buried.

PHASE 6

Responsive — designed per device, not resized

Desktop — full production planning

Three-pane workspace: scene navigator | script canvas | Doctor dock. Everything one click from the Reader; dense tables in Breakdown/Schedule.

Tablet — AD / PM / Location Manager (on set)

Two-pane: script | dock. Large touch targets, review-first: read sides, check breakdown, approve a variant, flag a note. Landscape-optimised.

Mobile — on-set quick actions

Single column, bottom thumb-nav (Reader · Breakdown · Doctor · Notes). Glanceable scene cards, big tap targets, quick actions (read sides, check element, approve, voice-note), offline read. Purpose-built cards — never shrunk desktop tables.
